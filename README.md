# 大A数据仓 · 两点半研判台

> 零依赖（纯 Python 标准库）的 A 股行业数据管线：**25 表 SQLite 历史库** + **14:30 六区研判** + **先证伪再上线**的研究台。

从东方财富 / 腾讯财经 / 蛋卷基金取数，落进一个自带 DDL 的 SQLite 历史库，再长出每日研判报告和 HTML 看板。没有 akshare、没有 pandas、没有 numpy —— `import` 的全是标准库，`git clone` 就能跑。

**这个项目最大的特点不是能选股，而是知道哪些不能选**：每条想上线交易的建议，都得先过对应的"验证台"；过不了就只作观察提示，并在报告里写明"不可作交易依据"。

---

## 为什么值得一看

- **零第三方依赖**：所有抓取用 `urllib` / 系统 `curl`，所有计算手写。装个 Python 就能跑，不用配环境。
- **数据可追溯**：联网抓到的每一行都必须落库（date 主键幂等覆盖），报告里的每个数字都能回查到表。库里 25 张表的 DDL 集中在 `src/common/history_db.py` 一处。
- **口径防错做得比功能多**：盘中跑不会写半截 bar、节假日占位行不入库、归档时间会告警、复权口径漂移会被拦下、外盘日K有交易日历闸。踩过的坑都写进了代码注释与报告。
- **会自我证伪**：`research/` 下的验证台与十万次随机取样迭代，专门用来打自己脸（见下节）。

## 14:30 六区（哪一区能当真）

每天 14:30 跑一次 `daily_1430.py`，输出六个区。**只有 A 区是可交易依据**，其余是观察/提示：

| 区 | 内容 | 独立验证结果 | 能否作交易依据 |
|---|---|---|---|
| A 持仓决策 | 多窗口估值分位共识 + 仓位灯 | 仓位灯让回撤减半（-7.8% vs -17.0%）；但十万网格诚实结论：74.5% 概率跑输"什么都不做" | ✅ 可交易，是**减震器**不是发动机 |
| B 短期行业 | 爆发力评分 Top5 | 独立回放超额 **−0.03%**（≈随机） | ❌ 不可 |
| C 抄底观察 | 庄家线四要素 | 三年窗口超额回撤 −24.7%，不晋升 | ❌ 只作观察 |
| D 恐慌监控 | 超跌反弹（指数，20日跌≥20%） | 28 轮独立行情、20 日 96% 赚钱（中位 +3.62%） | ⚠️ 只提示机会 |
| E 红利40日收益差 | 仓位档位尺 | 十万次迭代后平均超额 **+0.27%** | ⚠️ 只提示档位 |
| F 宽基深跌区 | 离半年线多远（≤−15% / ≤−18%） | 36 轮、30 日中位 +1.84%、胜率 69% | ⚠️ 只提示位置 |

完整证据链见 `AGENTS.md` 的「14:30 六区验证状态」与 `reports/` 下的验证报告。

## 先证伪，再上线

`research/` 里每个"验证台"都是同一个套路：把主观说法去主观化成确定性判据 → 长历史回放 → 十万次随机取样迭代（随机标的子集 × 随机时间窗 × 参数网格）→ 留存样本 + 邻域稳定性都不塌，才允许进模型。

被这套流程打掉的例子（都在 `reports/` 里）：

- **三重背离**（布林+MACD+RSI 共振）：顶背离增量只有约 0.7pp 且只近 5 年成立；**底背离是负增量**（深跌区叠加后 +2.54% → +1.45%）。真正有效的是"离半年线多远"这个**位置**。
- **超跌反弹选行业**：496 个板块 3.7 年只有 9 轮独立行情——超跌是"全市场一起跌"，选不出行业；同一规则用在**指数**上成立。
- **庄家抄底线**：十万网格前 30 候选留存全负 → 不晋升，只留在 C 区作观察。
- **红利40日收益差**：单样本看着 +1.5%，十万次迭代修正到 **+0.27%**，且换成含分红口径就转负 → 只能"减仓不清仓"。

## 快速开始

```bash
git clone https://github.com/<你的ID>/ashare-warehouse.git && cd ashare-warehouse

# 1) 建库（25 张表，自带样例数据）
cp data/market_history.sample.db data/market_history.db

# 2) 看一眼离线结论（不联网）
python src/jobs_build/daily_1430.py --no-refresh     # 六区研判
python src/jobs_build/generate_dashboard.py          # 生成 reports/投资看板.html

# 3) 联网取数（交易日 15:30 后最准；请温和抓取）
python src/jobs_fetch/update_data.py --snapshot-only # 快照，约 30 秒

# 4) 冒烟测试
python -m unittest discover -s tests                 # 19 项
```

要求：**Python 3.8+，无第三方依赖**（`python3` 在 Windows 上是 Store 占位符，统一用 `python`）。

> 样例库里只有最近 ~20 个交易日的真实行情，够跑通流程与看板；完整历史请自行运行取数脚本积累（历史库按 date 幂等覆盖，跑多少天攒多少天）。

## 目录结构

```
config/         配置（positions.example.json 是脱敏示例，复制成 positions.json 再用）
src/common/     基础层：paths / history_db(25表DDL唯一来源) / market_map / fetch_util / 技术指标
src/jobs_fetch/ 抓取层：只抓取+落库，不生成报告
src/jobs_build/ 构建层：算+报（14:30 六区、持仓建议引擎、看板、估值分位）
research/       研究层：验证台 + 十万次迭代 + 回测（每个策略一个脚本）
tests/          冒烟测试（可导入 / DB 入口 / 指标 / 单写入者）
data/           运行产物（快照 csv、历史库、缓存；见 data/README.md）
reports/        生成的报告与看板 + 验证结论
```

分层约定：`jobs_fetch` 不 import `jobs_build`；建表 DDL 只在 `history_db.py` 一处；行业映射与费用函数在 `src/common/` 唯一维护。

## 数据源

| 来源 | 用途 | 说明 |
|---|---|---|
| 东方财富 | 板块/ETF 快照、板块日K、资金流、涨跌停池、龙虎榜、指数估值 | 首选浏览器自动化，Python 直连需 cookie |
| 腾讯财经 | 一级行业、外盘指数、非股票 ETF 日K | 东财限流时的替代源 |
| 蛋卷基金 | 行业指数 PB/PE 分位（估值尺） | 数据自带日期字段，按源日期入库 |
| 新浪财经 | 日K交叉校验、实时点位 | 独立源，用于验证而非主链 |

所有接口串行请求 + 间隔 sleep；被限流时按"每窗口约百次请求 + 冷却 15 分钟"排程。**请自行遵守各数据源的使用条款，仅供个人研究。**

## 已知边界（写在前面）

- 盘中运行记录的是盘中值；**收盘后重跑一次**才会落定为收盘口径（`archive_snapshots` 会在盘中/周末归档时告警）。
- 外盘日K有交易日历闸，但日历来自本地指数 CSV（2016-08 起），更早的历史日期不校验。
- 没有第三方依赖 = 没有 `pandas` 的便利，长历史统计靠手写循环，十万次迭代要跑一会儿。
